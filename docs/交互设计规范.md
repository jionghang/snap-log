# SnapLog 交互设计规范

这份规范回答两个问题：**什么样的界面算"用户友好"**，以及**这个软件该怎么做到**。
改界面前先读它；改完按下文清单自检（能自动验的都已经接进 `--ui-smoke`）。

## 依据

行业里被引用最多的两份仍然够用：

- **Nielsen 十项可用性启发式**（Jakob Nielsen，1994 提出、至今是事实标准）：
  状态可见、贴近现实、用户可控、一致、防错、识别优于回忆、灵活高效、极简、帮助用户从错误中恢复、帮助文档。
- **Shneiderman 八条界面设计黄金法则**：追求一致性、允许常用用户走捷径、提供信息反馈、
  设计对话要有收尾、防止错误、允许轻松撤销、让用户主导控制权、降低短期记忆负担。

平台约定（Windows 桌面 / Fluent）和本项目自己的定位，把这两份原则落成下面的十条。

## 先记住这个软件的定位

> 它是一个安静的后台工具：用户只关心四件事——**在不在记录、每天几点跑、开不开机自启、最近一次推送成没成。**

推论（所有取舍都从这里来）：

- 界面上只回答这四个问题；其他信息收进提示、日志或直接不给（要改改配置文件）。
- 只有一条自动执行路径，没有"手动生成/手动推送"——少一个入口，就少一类出错和困惑。
- 平时安静，出事必须出声（失败冒泡），成功不打扰。

## 十条规范

### 1. 状态可见性

运行状态、下次执行时间、最近一次结果必须随时可见（概览页四个卡片就是干这个的）。
**失败要主动提示**（托盘气泡），成功保持安静——这是有意的取舍：这个工具的价值就在于"不需要盯着"。

### 2. 说人话，说软件的话

- 用软件用语，不用口语：「记录数」不是「用了几条」，「稍后设置」不是「以后再说」，「请保存」不是「记得点保存」。
- 不用 AI 味的排版符号：不写「」引号堆砌、①②③圈号、成串破折号。
- 术语全项目统一：飞书那一侧一律叫**推送**（不混用"写入""上传"）；状态一律"已推送/未推送"。

### 3. 界面上少写字

- 一段解释默认**收进问号提示**：界面只留"要做什么"，"为什么、边界情况"放提示里悬停展开。
- 判据：一行字说不完的说明，就不该直接铺在界面上。
- **提示不能是空的**——"少写字"不能以丢信息为代价（自检会逐个检查问号是否挂着文字）。

### 4. 渐进披露与"能不给就不给"

能写死的参数不进界面（抓取节奏、识别引擎、重试、保留策略都有验证过的默认值），
设置页只留"确实有人要改"的：大模型接入、飞书接入、不记录的软件、附加要求、工作项目与字段映射。
想要更多参数的人可以编辑 `appsettings.json`——界面不为 1% 的人变复杂。

### 5. 一张脸：所有界面同一套系统

颜色、字号、间距只从 `Palette.axaml` / `Theme.axaml` 取，页面里不写死数值；
同类元素同一形态：列表列对齐、**数字列右对齐**、状态用"文字 + 颜色"而不是只靠颜色。
新增构件先进 `Ui.cs` 的工厂方法，不在页面里各画一套。

### 6. 键盘可用（桌面软件的底线）

- 对话框：**Esc = 取消**，**Enter = 默认按钮**；破坏性操作里默认键落在**取消**上（手快按回车不能删掉记录）。
- 次要窗口（记录详情、总结正文、托盘菜单）：**Esc 关闭**。
- 搜索框：**Esc 清空**关键词。
- 打开窗口后焦点落在主操作上；按钮 Tab 顺序自上而下、自左而右。

### 7. 防止出错

- 破坏性操作必须确认，并说明后果（"记录和它的截图文件都会被删除，这个操作不可撤销"）。
- 危险按钮用浅红描边（`Button.danger`），不做成醒目的实心红。
- **不允许出现"填不了的表单"**：功能开关关着时，接入信息照样可以填写（否则新用户第一次配置就被挡在门外）。
- 会发网络请求的按钮防连点（测试连接、自动匹配）。

### 8. 错误要能自愈

错误信息三要素：**发生了什么 + 为什么 + 下一步怎么办**（例："配置没能写入磁盘……请检查配置目录的写权限"）。
失败的动作不产生副作用：生成失败不删旧总结、推送失败不打"已写"标记、清理不碰待识别记录。
用户能做的补救尽量内置（到点自动重做失败或遗漏的那一天）。

### 9. 可访问性底线

- 正文文字对比度 ≥ 4.5:1。实测（白底）：Ink 17.7、Ink2 7.6、Ink3 4.8、Accent 5.2、
  成功/警告 5.0、危险 6.5，**在用的颜色全部达标**；`Ink4`（2.5:1）只作装饰、不承载信息。
- 可点击元素热区不小于 18px（问号提示从 16px 提到 18px）。
- 只显示图形/符号的控件要有**可访问名**（问号提示的文字同时登记给读屏软件）。
- 信息不能只靠颜色区分（"已推送/未推送""成功/失败"都有文字）。

### 10. 隐私要明说

发送什么、发到哪、什么时候发，三句话写清楚（首次开启每日流程时确认一次并记住）；
诊断信息输出脱敏（App ID、token 只留头尾）；截图与文字默认只存本机。

## 本轮体检记录（2026-10-05）

拿上面十条逐项过了一遍代码与截图，发现并处理：

| 检查项 | 体检发现 | 处理 |

| 焦点（第 6 条） | 对话框打开后焦点不定，键盘用户要先 Tab | 已修：焦点落在默认按钮上 |
| 可访问性（第 9 条） | 问号对读屏软件只是"?"；热区 16px | 已修：登记可访问名；热区提到 18px |
| 防错（第 7 条） | "启用大模型总结"关着时整个模型列表被禁用——**新用户第一次填密钥就被挡住** | 已修：去掉禁用，与飞书卡片保持一致 |
| 防错（第 7 条） | "测试连接"可连点，重复发请求 | 已修：测试期间忽略再次点击 |
