# SnapLog 2.0 交付说明

这份说明记录 2.0 这一版的交付内容、验证方式，以及需要人工补充确认的一处。

## 这一版改了什么

**界面重写为 Avalonia**（1.x 是 WinForms）

- 主窗口从"八个标签页"改成**四个入口**：概览 / 抓取记录 / 总结记录 / 设置。
- 概览页是主场：只放"现在是否在记录、每天几点自动跑、开机要不要自启、最近一次总结的结果"。
- 参数从五十多个压到 **设置页 8 个 + 进阶折叠区 4 件**；其余（抓取节奏、识别引擎、图片选项、重试与超时、保留策略……）一律用默认值，要改就编辑 `appsettings.json`。
- 日志不再铺在界面上，收进「关于」窗口的入口。
- 设计系统集中在 `Ui/Palette.axaml`（颜色）+ `Ui/Theme.axaml`（字号/控件样式）；托盘右键菜单是自绘的 Avalonia 弹窗，不是 WinForms 的灰菜单。
- 手动执行入口全部撤掉：只有"到点自动跑"这一条路径。

**正确性修复**（都是 1.x 就存在、或 2.0 开发中暴露的问题）

| 问题 | 修法 |
|---|---|
| 飞书表里同一天出现两行 | 改为**只总结已经过完的那一天**（不再"准点跑今天"），当天数据落库后不再变化 |
| 生成失败会把旧总结删掉 | 改成**生成成功之后**才删旧记录 |
| 清理会删掉还没识别的记录 | 按时间的清理跳过 `Pending`；用户主动删除不受影响 |
| 清理可能删到别人的图片 | 只删符合本程序命名规则的截图 |
| 保留策略在托盘模式从不执行 | 每次启动清理一次 |
| 记录暂停后定时任务照样跑（文字照发） | 加暂停门禁 |
| 早上补跑吃掉当晚准点执行（日报每天晚一天） | 判定口径改成"今天这一份跑了没有" |
| 推送窗口 1 天，推送失败即永久丢失 | 默认 2 天 |
| 单实例、配置路径、`CopyInto` 漏字段等 | 一并修正 |

**隐私**

- `--diagnose` 输出脱敏：App ID、app_token、table_id 只留头尾，接口地址只留主机名。
- 隐私文案不再承诺"截图不会外发"（带图模式下原图确实会随请求上传），改成按实际模式说明。
- 首次开启每日流程时弹确认框；配置里开着但没确认过的情况，启动时会补弹一次。

## 怎么验证

```cmd
build.cmd                              :: 应输出：0 个警告 0 个错误
run.cmd --selftest                     :: 应输出：自检结论 : 通过 ✅
run.cmd --ui-smoke                     :: 界面自检 5 条用例全绿：
                                       ::   状态一致性 / 退出路径 / 清理不误删待识别 / 调度语义 / 托盘菜单
run.cmd --diagnose                     :: 敏感字段应为掩码形式
run.cmd --ui-shots [目录]              :: 逐页导出 PNG；不指定目录时写在自检沙盒里
```

`--ui-smoke` 会真的构造每个页面并逐个点击控件（跳过会联网的三个按钮），其中 5 条是回归用例，改坏了会立刻变红。

`--selftest` 拿不到前台窗口时（锁屏或非交互会话）会退化为 ⚠，并提示用 `--target <关键字>` 指定一个有文字的窗口重跑——这是环境限制，不是缺陷。实测 `--selftest --target Taskmgr` 输出「自检结论 : 通过 ✅」。

**自检类命令在临时沙盒里运行**：`--selftest` / `--ui-smoke` / `--ui-shots` / `--menu-preview` / `--capture-stress` 会把配置和数据库复制到 `%TEMP%\snaplog-probe\<时间戳>\`，所有写入落在副本上（显式传 `--data` 时按你指定的目录来，`--menu-preview` 的真机预览就是这么做的）。命令开头会打印沙盒路径。

## 托盘菜单：已在真机上验证（含一个已修的定位 bug）

用 `--menu-preview [秒]`（开发用命令）把同一个托盘菜单摆到真实桌面，在真机上核到三件事：

- **位置对了**：日志 `托盘菜单定位：248×222 @ (1408,814)　鼠标=(1640,1044)　工作区=(0,0,1920×1040)`
  —— 菜单贴在托盘旁边，且落在工作区内（不再是屏幕左上角）。
- **内容和坐标是真的**：UIA 按名字读到 `开始记录 / 打开 SnapLog / 打开数据目录 / 退出 SnapLog`，
  坐标真实可用（例如 `退出 SnapLog @ 1425,986 214×33`）。
- **点"退出"真的结束进程**：点该菜单项后日志出现 `托盘菜单：点了 退出 SnapLog`，随后进程消失。

### 修掉的定位 bug（用户报过"菜单不在托盘旁"）

三个原因，都已修：

1. **工作区取错了源**：Avalonia 的 `Screens` 在这个进程里返回空矩形，`Clamp` 之后菜单只能落在 (0,0)
   （屏幕左上角）。改成用 WinForms 的 `Screen.PrimaryScreen.WorkingArea`——它给的就是物理像素，
   和窗口定位的坐标系统一。
2. **Avalonia 的 `Window.Position` 对这个窗口不生效**：无边框 + Topmost + SizeToContent 的组合下，
   先设位置、Show 之后再校正都不动。改成布局完成后用 Win32 `SetWindowPos` 直接移动窗口。
3. **光标位置**改用 Win32 `GetCursorPos`：托管的 `Cursor.Position` 在某些环境里读出来是 (0,0)，
   会把菜单算到屏幕角落。

### 仍只能人工确认的部分

在 Windows 10 的隐藏图标浮出层里，**用脚本点那个托盘图标**做不到：UIA 报的坐标是屏幕外假值、
也不支持 UIA 动作，合成鼠标命中不了。功能本身已由上面的真机验证与 `--ui-smoke` 的"托盘菜单"用例
覆盖；人手点一下属于补充确认，不影响交付。

## 原「已知未验项」记录（已闭环，保留备查）

**Windows 10 隐藏图标浮出层里"人手右键托盘图标"这一下，没有在真机上复现过。**

- 程序侧已验：托盘图标确实被加进托盘（按名字能搜到）；菜单的内容、自绘样式、位置算法、点"打开 SnapLog"唤回窗口、点"退出 SnapLog"走退出路径，都由 `--ui-smoke` 的"托盘菜单"用例覆盖并通过。
- 真机侧已验：点窗口 X 之后窗口不可见、进程仍在（实测两次）。
- 为什么没验成：Win10 通知区域里那个图标，UIA 报的坐标是屏幕外的假值（`y=-6483` / `-8296`），`ScrollIntoView` 纠正不了，`Invoke`/`Select` 模式不支持，键盘导航拿不到焦点，浮出层本身对合成点击时开时不开——**脚本点不中它**。这是测试手段的限制，不是功能缺陷的证据。
- **人工确认（几秒）**：点开任务栏 `^`，鼠标移到 SnapLog 图标（蓝底白快门），**左键单击或右键** → 应出现白底圆角菜单：顶部一行"正在记录/已暂停"，下面 暂停记录 / 打开 SnapLog / 打开数据目录 / 退出 SnapLog；点「退出 SnapLog」进程应消失。不符合就把现象提出来。

## 第二轮修订（文案、排版、自检沙盒）

按第二轮反馈改的：

- **总结记录页**：表头"总结的是哪天 / 用了几条"改成"**总结日期 / 记录数**"；"写入飞书"列原来填的是时间戳，
  和"生成时间"经常一模一样，看不出状态——现在明确显示绿色「**已推送**」/灰色「**未推送**」，
  页头合计也改成"已推送 N 条"。提示语"点一行看正文"改成"选择一行查看正文"。
- **详情窗排版**：记录详情与总结正文的正文，从 13px 密排改成 **14px / 行高 22**（收在 `Ui.BodyText` 一处），
  多行说明的行高统一为 18；`--ui-shots` 逐页核过。
- **全界面文案**：把"点一行看详情 / 还没配好 / 记得点保存 / 不会跑 / 勾掉 / 以后再说"这类
  口语化说法统一成软件用语，覆盖概览、抓取记录、总结记录、设置、关于、首次运行和状态栏。
- **清理死代码**：删掉手动执行时代遗留的、没有调用方的方法（设置页里那个"保存并推送"、`AppServices`
  里只被它引用的三个手动包装方法）。

### 顺带修掉的一个真实事故：自检把改动写进了真实配置

`--ui-smoke` 会模拟点击开关和"保存"按钮，而它当时读写的配置是**真实那份**。这次试用里它把
"启用大模型总结""启用飞书推送"关掉后写了回去，还多出两个"备用模型"；其中推送开关被关，会让当晚
自动推送被跳过（总结照常生成）。处理：

- 真实配置已按事发前的备份逐字段核对并恢复原样（受损版本留在 `backup-config-before-repair-<时间戳>\`，备查）。
- 根因修复：自检类命令统一进沙盒（见"怎么验证"）。实测同一命令运行前后，真实配置指纹完全一致。

## 第三轮修订（说明文字收进问号提示、对齐）

- **说明改问号**：成段的解释不再铺在界面上，收成标题/标签旁的"?"，鼠标悬停才展开。涉及概览三张卡片、
  设置页 11 处字段与分区说明、抓取记录与总结记录页头、关于窗口、两个详情窗；首次运行的提示也压到一行。
  界面上只留"要做什么"，"为什么、边界情况"进提示。
- **对齐**：识别字数、记录数改成右对齐并留出列间距；"不记录的软件"从"半截被裁掉的滚动区"改成
  多列流式排列；详情窗去掉挤在标题下的说明行，标题/信息行/正文的间距统一。
- **自检新增"问号校验"**：`--ui-smoke` 会先展开折叠区，再逐个检查每个"?"都挂着非空提示文字
  （5 个页面共 17 个：概览 3、设置 11、抓取记录 1、总结记录 1、关于 1；另有详情窗各 1 个）；
  提示要是空的会直接变红——"少写字"不能以丢信息为代价。

## 其他

- 改动前的真实数据备份在 `%LOCALAPPDATA%\SnapLog\backup-before-yesterday-only-<时间戳>\`（数据库 + 状态 + 配置各一份）。
- 真机验证用的脚本在 `%TEMP%\snaplog2-real\`（截屏 + 模拟点击 + UIA 查询），可复用。
- 2.0 与 1.x 共用同一个数据目录和单实例锁：同时只能跑一个；日志文件名已分开（2.0 是 `snaplog2-*.log`），便于排查时区分。
