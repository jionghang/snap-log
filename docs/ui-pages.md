# 界面结构清单（分组 / 布局 / 文案）

这份清单是界面整理后的基线：每个页面有哪几块、每块有哪些行、文案怎么写的。
改动界面时按它对齐，避免再出现"同一页里两种风格"。

2.0 的界面是 Avalonia（1.x 是 WinForms），结构从"八个标签页"改成"四个入口 + 弹窗"。

---

## 全局约定

- **导航**：左侧 184px 固定宽度，四个入口（概览 / 抓取记录 / 总结记录 / 设置）。选中项用浅蓝底 + 蓝色文字；底部是三个轻量入口（打开数据目录 / 查看运行日志 / 版本号）。
- **状态栏**：窗口底部一条，左边一行状态文字（最近一次动作、跳过原因），右边运行状态徽标（记录中 = 绿，已暂停 = 橙）。
- **行**：左边灰色行标题（固定 132px 宽，放得下最长的"自动生成总结时间"），右边是控件；说明文字一律灰色、限宽 520px 自动换行，与控件左对齐。
- **卡片**：白底 + 1px 浅灰边 + 10px 圆角 + 18px 内边距；卡片之间 16px；卡片内元素之间 14px。组间靠留白区分，不加分隔线。
- **按钮**：动宾短语，需要弹窗的一律带省略号（如"高级设置…"、"按日期生成…"）；主操作（开始记录 / 保存 / 生成 / 删除确认）用蓝色实心，其余为普通按钮，删除用红色文字。
- **数字与时间**：时间统一 `HH:mm`，日期时间 `yyyy-MM-dd HH:mm:ss`，列表里的时间用 `MM-dd HH:mm(:ss)`。
- **状态用中文**：已识别 / 无文字 / 失败 / 待识别（不再出现 Ok / Pending 这类枚举名）。
- **开关即生效**：概览页的开关/时间改完立刻写盘并生效；设置页里的文本框需要点"保存"，点完就地显示 `已保存 21:30`。
- **参数取舍**：界面上只留"必须由用户提供"的（两处接入信息）和"确实会想改"的（一个时间、一个开关、四件进阶项）。其余一律用默认值，不出现在界面上。

## 主窗口（SnapLog · 屏幕活动记录）

### 概览

- 卡片：运行状态
  - 状态点 + 大字状态（正在记录 / 已暂停）+ 一行说明（暂停期间不截图，每日自动任务也不会执行）
  - 操作按钮：`暂停记录` / `开始记录`（唯一的主操作）；右侧是状态徽标
  - 一行小字统计：`本次运行新增 N 条　·　最近一次抓取 HH:mm:ss（窗口标题）　·　累计 N 条`
- 卡片：最近一次日报（这一页的主角）
  - 徽标 + 一行大字：`昨天 02:30 已写入飞书` / `今天 22:05 已生成，还没写入飞书` / `昨天 22:05 没有生成成功`
  - 一行明细：`覆盖 2026-10-03　3 条记录　模型名　耗时 5.3 秒`（失败时这一行放失败原因）
  - 按钮：`立即重跑今天`（主操作）、`写入飞书`、`查看全部总结`
  - 空状态：`还没有生成过日报` + `配好大模型和飞书之后，每天到点会自动生成并写入；也可以点右边先手动跑一次。`
- 卡片：每天自动执行
  - 一行：`[开关] 每天 [时间 02:30] 自动完成` + 右侧灰字状态（`明天 02:30（今天已跑）` / `待补跑（设定 02:30 已过）` / `已关闭`）
  - 说明一：`到点依次执行：① 识别这些截图里的文字（白天先只截图，把耗 CPU 的活儿留到这个时间） → ② 生成当天的总结 → ③ 写入飞书多维表格。`
  - 说明二（橙色，仅当没配好时出现）：`还差一步：去设置 → 大模型填好接口地址、模型名称和 API Key，否则生成总结会失败。`（飞书没配好时换成第 ③ 步的提示）
  - 迁移链接（仅当 1.x 三个时间不一致时出现）：`检测到旧版为三个步骤分别设了时间，点这里统一为 02:30`
  - 脚注：`到点没开机，下次启动时补跑；记录处于暂停状态时不会执行。`
- 卡片：启动与维护
  - `开机自动启动` + 开关（说明：登录后自动在托盘里开始记录，不弹窗口）
  - `打开数据目录`

### 抓取记录

- 卡片：筛选（无标题、无按钮）
  - 一行：关键词（占位"搜窗口标题或识别到的文字"，输入后 350ms 自动查询）+ 日期（今天 / 近 7 天 / 近 30 天 / 全部）
  - 说明：`只列出最近 300 条；更早的内容按需放宽日期或直接搜关键词。`
- 卡片：列表 + 详情（列表占满剩余高度，详情固定在下方）
  - 列表列：时间 / 进程 / 窗口标题 / 字数 / 状态；单元格一律单行 + 省略号；列表最高 320px
  - 详情（标题 `这一条记了什么`）：`时间　进程　状态　字数`（提示/错误另起一行），按钮 `复制文字` / `打开截图` / `删除这条`，下面是完整识别文字（可选中、可滚动）
  - 空状态：`点上面任意一行，这里显示完整内容。`；空结果：`这段时间没有记录。放宽日期或清空关键词试试。`

### 总结记录

- 卡片：操作
  - 按钮：`生成今天的总结`（主操作）、`按日期生成…`、`立即写入飞书`、`打开总结目录`
  - 说明：生成总结会把记录内容发送到你配置的大模型接口，仅在你点下按钮（或定时任务到点）时发生
- 卡片：列表 + 详情
  - 列表列：生成时间 / 覆盖 / 触发 / 模型 / 条数 / 结果
  - 详情：`#id　时间区间　触发　模型　记录条数　耗时　附带截图　已写入飞书时间`；失败时显示原因；`打开文件` / `打开所在目录`；下面是总结正文

### 设置

- 卡片：大模型（副标题是活的状态行：绿色 `已配置，可以生成总结` / 橙色 `还没配好：接口地址、模型名称、API Key 三项都要有`）
  - `启用大模型总结`、`接口地址`、`模型名称`、`API Key`（密文）
  - 每个字段下面一行灰字说明（是什么、去哪拿、能不能留空）
  - 若配置里有多个模型：灰字提示"另有 N 个备用模型…只在 appsettings.json 的 Providers 里维护"
  - 按钮：`保存`（主操作）、`测试连接`
- 卡片：飞书（副标题同样是状态行）
  - `启用飞书推送`、`App ID`、`App Secret`（密文）、`多维表格 token`、`数据表 ID`
  - 按钮：`保存`（主操作）、`立即写入飞书`
- 卡片：进阶设置（折叠区，默认收起，标题 `进阶设置（多数情况不用改）`）
  - `不记录的软件`（一行一个进程名；密码管理器这类填这里）
  - `附加要求`（追加到提示词末尾）
  - `工作项目清单`（项目名 + 说明，可增删）
  - `飞书字段映射`（左边选总结字段，右边填飞书列名）
  - `保存`
- 卡片：其他
  - `打开数据目录`、`关于`、`退出 SnapLog`

### 生成总结（760×660）

- `要总结的日期`（日期选择，默认今天）+ 说明"默认是今天；也可以选过去的某一天补生成"
- `发送内容`：一行摘要（仅文字 / 仅截图 / 文字与截图 + 字符数 + 图片张数）
- 首次使用时出现勾选项：`我确认：本次会把上述内容发送到配置的大模型接口`
- `将要发送的内容（不含图片本身）`：等宽字体的预览（模型、字符数、附带截图清单、system / user 提示词全文）
- 底部状态行 + 按钮：`开始生成`、`关闭`
- 生成成功后把正文替换进预览区，并打开保存下来的文件

### 日志

不提供独立的日志窗口：失败时托盘气泡会说明原因，真要查日志走设置 → 关于 → 打开日志目录。

### 关于（640×自适应高）

版本 / 运行状态 / 开机自启动 / 文字识别 / 大模型总结 / 飞书推送 / 数据目录 / 数据库 / 运行时 / 程序路径。
底部按钮：`复制诊断信息`、`打开数据目录`、`关闭`；以及命令行诊断命令的提示。

### 首次运行（580×自适应高）

"已经在托盘里开始记录了" + 四条须知（数据在本机、只有生成总结才联网、三个自动任务在概览页、敏感窗口去高级设置里排除）+ "建议先做两件事" + `知道了`。

### 确认框（470×自适应高）

标题 + 正文 + 右侧按钮（取消 / 确认）。删除类操作用红色确认按钮，并写明"这个操作不可撤销"。

## 托盘菜单（自绘的 Avalonia 弹窗，不是系统灰菜单）

- `暂停记录` / `开始记录`
- `打开 SnapLog`
- `打开数据目录`
- 分隔线
- `退出 SnapLog`

样式：白底 + 1px 边 + 10px 圆角 + 柔和阴影，宽度 248，行高 34，鼠标悬停变浅灰；点到别处自动收起。位置贴着鼠标（托盘）弹出，并夹在屏幕工作区内。

托盘气泡只用于两件事：定时任务失败、首次运行的说明（后者等图标真正进托盘之后再弹）。

## 已知待验（2.0 交付时留下的唯一一项）

**托盘右键菜单在 Windows 11 隐藏图标浮出层里的那次真实右键，没有在真机上复现过。**

- 程序侧已验：托盘图标确实被加进托盘（自动化界面检查按名字搜到了 `SnapLog · 记录中`）；菜单的内容、自绘样式（白底圆角，不是系统灰菜单）、位置算法（贴着托盘往左上展开、越界夹回工作区）、点`打开 SnapLog`唤回窗口、点`退出 SnapLog`走退出路径，都由 `--ui-smoke` 里的托盘菜单用例覆盖并通过。
- 真机侧已验：点窗口 X 之后窗口不可见、进程仍在（实测两次）；托盘图标存在。
- 缺的那一步：Win11 会把新图标折叠进 `^` 浮出层，而**合成点击**（脚本模拟的鼠标）在浮出层里不可靠——同一坐标有时能展开有时不能，导致无法稳定地用脚本完成右键→点菜单项。这是测试手段的限制，不是功能缺陷的直接证据。
- 人工确认只要几秒：点开任务栏 `^`，找到 SnapLog 图标（蓝底白快门），**左键单击或右键**一下——应弹出白底圆角菜单（顶部一行运行状态，下面：暂停记录 / 打开 SnapLog / 打开数据目录 / 退出 SnapLog）。若弹出的是灰色系统菜单或什么都不弹，请提 issue。
- 另外注意：托盘图标**左键单击也会弹菜单**（双击才打开主窗口）。这是刻意加的——Windows 的隐藏图标浮出层对左键的响应比右键可靠，多给一条路。
