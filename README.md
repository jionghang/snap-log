# SnapLog 2.0

SnapLog 是一个 Windows 桌面工具：记录屏幕活动、识别屏幕上的文字，每天在设定时间把一整天的工作内容整理成一份小结，并写入飞书多维表格。

程序常驻托盘，平时安静运行；只有到设定时间才会把识别出的文字发送到你配置的模型接口。

---

## 一、适用场景

- 工作分散在多个窗口与系统之间，事后回顾需要逐处翻找。
- 希望每天自动得到一份按天归档的工作小结，并汇集到飞书表格，便于复盘与汇报。
- 记录内容保存在本机；发送对象、发送时机与发送内容都由自己配置。

不适用：实时监控、跨设备同步、多人协作编辑。

## 二、工作流程

平时：跟随前台窗口切换自动截图，并识别画面上的文字。截图与文字保存在本机。

每天在设定时间，程序按顺序执行三步：

1. **批量识别**：把前一天保存的截图识别成文字。
2. **生成总结**：把识别出的文字交给大模型，写成一份工作小结。
3. **推送飞书**：把小结写入飞书多维表格，一天一行。

配套约定：

- 总结对象是已经结束的那一天，晚上加班的记录也会包含在内。
- 设定时间电脑未开机时，会在下次启动后自动执行。
- 失败或遗漏的日期会在下一次执行时重做，不需要人工干预。

## 三、界面与配置

程序启动后驻留在托盘。首次运行会打开说明窗口，可从中进入设置。界面共四个页面：概览、抓取记录、总结记录、设置。

### 概览

程序的主页面，回答四个问题：现在是否在记录、最近一次总结的结果、每天几点自动执行、是否开机启动。

| 项目 | 配置方式 | 效果 |
|---|---|---|
| 记录状态 | 顶部显示"正在记录 / 已暂停"，下方按钮切换 | 暂停期间不截图，也不执行每日流程 |
| 最近一次总结 | 无需配置，自动显示 | 显示覆盖日期、记录条数、所用模型、耗时与推送状态 |
| 每天自动执行 | 开关 + 时间 | 开启后每天在设定时间执行识别、生成、推送三步；这是程序的核心开关 |
| 开机自动启动 | 开关 | 登录 Windows 后自动在后台启动并开始记录 |

### 抓取记录

列出程序抓取到的屏幕记录：时间、进程、窗口标题、识别字数、状态。支持按关键词与时间范围筛选。

选择一行查看详情：该时刻的截图、识别出的完整文字，以及删除入口。默认最多列出最近 300 条。

### 总结记录

列出生成过的每日总结：生成时间、总结日期、记录数、飞书推送状态、生成结果。

选择一行查看正文。正文可选中复制，也可打开程序保存的文本文件。

### 设置

设置页是接入配置，分三段。

**大模型配置**（生成总结的模型接口）

| 项目 | 说明 |
|---|---|
| 启用大模型总结 | 总开关。关闭时不调用任何模型接口，只保留本地记录 |
| 接口地址 | OpenAI 兼容服务的地址，一般以 /v1 结尾 |
| 模型名称 | 服务商提供的模型名 |
| API Key | 密钥；留空时从环境变量读取 |
| 添加模型 | 支持配置多个模型：按顺序调用，前一个失败自动换下一个 |
| 测试连接 | 逐个模型发一次小请求，验证地址、密钥与模型名是否匹配 |

**飞书配置**（总结的推送目标）

| 项目 | 说明 |
|---|---|
| 启用飞书推送 | 总开关。关闭后，每日流程不再推送到飞书 |
| App ID / App Secret | 飞书自建应用的标识与密钥（App Secret 留空时从环境变量读取） |
| 多维表格 token | 表格链接中 /base/ 之后的部分 |
| 数据表 ID | 形如 tblxxxxxxxxxxxxxx |
| 保存飞书设置 | 保存接入信息；表格列名的对应关系在"高级设置"中配置 |

推送为覆盖写入：同一天的总结只占一行，重复执行不会产生重复记录。

**其他**：高级设置、关于、退出 SnapLog 三个入口。

### 高级设置

独立窗口，按用途分四组：

| 分组 | 内容 |
|---|---|
| 记录范围 | 勾选不参与记录的程序；清单取自历史记录中出现过的程序，不需要手打进程名 |
| 总结偏好 | 附加要求：内容原样追加到提示词末尾，用于补充写作要求，例如"只写完成的事和结论" |
| 工作项目 | 总结的主要工作主题按这些项目分组；说明写得越具体，归类越准 |
| 飞书字段映射 | 左侧选总结字段，右侧填对应的飞书列名；支持"按列名自动匹配"读取表头后配对 |

### 托盘

托盘图标提供：记录状态、暂停/开始记录、打开 SnapLog、打开数据目录、退出 SnapLog。

关闭主窗口只是收进托盘，程序仍在记录；要完全退出，请使用托盘菜单或设置页中的"退出 SnapLog"。

## 四、安装与运行

**直接使用**：下载发布页的压缩包，解压到任意目录（自包含版本，不需要安装 .NET 运行时），双击 SnapLog.exe 运行。程序默认最小化到托盘。

**从源码构建**：需要 .NET 10 SDK。

```
build.cmd        构建（输出到 src\SnapLog\bin\Release\net10.0-windows10.0.19041.0\）
run.cmd          启动程序
publish.cmd      生成自包含发布版（输出到 publish\，约 140 MB）
```

**数据与日志位置**：`%LOCALAPPDATA%\SnapLog\`

| 内容 | 位置 |
|---|---|
| 数据库 | activity.db（屏幕记录与总结记录） |
| 截图 | images\（按日期分目录） |
| 生成的小结 | summaries\（文本文件） |
| 日志 | logs\ |
| 配置 | appsettings.json |

## 五、隐私

- 截图与识别文字保存在本机，不上传；截图默认保留 30 天，可按需调整。
- 只有在每天设定时间生成总结时，才会把识别出的文字发送到你自己配置的模型接口。默认只发送文字；是否附带截图取决于大模型配置中的"发送内容"。
- 推送到飞书的内容是总结正文与其元数据（日期、条数、模型等）。
- 不希望在记录里出现的程序，可在"高级设置 → 记录范围"中排除。

## 六、配置文件参数

界面之外的参数集中在 `%LOCALAPPDATA%\SnapLog\appsettings.json`。程序启动时读取该文件，修改后重启生效；删除该文件会恢复全部默认值。下表只列常用项，均可留空或删除，表示使用默认值。

### 抓取

| 参数 | 默认值 | 含义 |
|---|---|---|
| `Triggers.CaptureCycleMinutes` | 10 | 同一窗口的抓取周期（分钟） |
| `Triggers.ForegroundSettleMilliseconds` | 5000 | 窗口切换后等待多久再截图（毫秒） |
| `Triggers.MinSecondsBetweenCaptures` | 20 | 两次抓取的最小间隔（秒） |
| `Triggers.ExcludedProcesses` | ["snaplog"] | 不记录的进程名 |
| `Triggers.ExcludedWindowTitles` | ["Program Manager"] | 不记录的窗口标题（精确匹配） |
| `Capture.MaxImageDimension` | 2560 | 截图最长边上限（像素） |
| `Capture.ImageRetentionDays` | 30 | 截图保留天数 |
| `Capture.ImageDirectory` | 空 | 截图存放目录；留空表示数据目录下的 images |

### 识别

| 参数 | 默认值 | 含义 |
|---|---|---|
| `Ocr.Engine` | PaddleOcr | 识别引擎：PaddleOcr（离线）或 WindowsMedia（系统内置） |
| `Ocr.Mode` | Realtime | 识别方式：Realtime（抓到即识别）或 ScheduledBatch（定时批量） |
| `Ocr.PaddleModel` | V6Tiny | PaddleOCR 模型档位 |
| `Ocr.PaddleThreads` | 4 | 识别线程数 |
| `Ocr.MinTextLength` | 4 | 少于该字数的记录标记为"无文字" |
| `Ocr.DropEmptyRecords` | true | 不保存未识别出文字的记录 |

### 存储与清理

| 参数 | 默认值 | 含义 |
|---|---|---|
| `Storage.DataDirectory` | 空 | 数据目录；留空表示 `%LOCALAPPDATA%\SnapLog` |
| `Storage.RecordRetentionDays` | 0 | 记录保留天数；0 表示不自动清理 |
| `Storage.DatabaseFileName` | activity.db | 数据库文件名 |

### 模型请求

| 参数 | 默认值 | 含义 |
|---|---|---|
| `Summarization.PayloadMode` | TextOnly | 发送内容：仅文字、文字加截图 |
| `Summarization.MaxImages` | 6 | 附带截图时的最多张数 |
| `Summarization.MaxInputCharacters` | 24000 | 送入模型的记录正文上限（字符） |
| `Summarization.MaxRecords` | 200 | 送入模型的最大记录条数 |
| `Summarization.RetryCount` | 2 | 单模型重试次数（仅对可恢复错误） |
| `Summarization.RequestTimeoutSeconds` | 120 | 单次请求超时（秒） |
| `Summarization.SystemPromptOverride` | 空 | 完全替换系统提示词；留空使用内置提示词 |
| `Summarization.ExtraInstructions` | 空 | 追加到提示词末尾的写作要求（界面中可改） |

### 飞书推送

| 参数 | 默认值 | 含义 |
|---|---|---|
| `Feishu.PushLookbackDays` | 2 | 推送范围：只写最近 N 天生成且未写入的总结 |
| `Feishu.PushAfterSummary` | false | 生成总结后立即推送，不等定时推送时间 |
| `Feishu.MaxTextLength` | 2000 | 单条写入的正文上限（字符） |
| `Feishu.BatchSize` | 200 | 单批写入条数 |

### 日志与界面

| 参数 | 默认值 | 含义 |
|---|---|---|
| `Logging.Enabled` | true | 是否写日志文件 |
| `Logging.Level` | Info | 日志级别 |
| `Logging.RetentionDays` | 7 | 日志保留天数 |
| `Ui.StartMinimizedToTray` | true | 启动时只显示托盘图标 |
| `Ui.CloseToTrayInsteadOfExit` | true | 关闭窗口时收进托盘而不退出 |

密钥也可以放在环境变量中，避免写入配置文件：`AppSecretEnvironmentVariable` 与 `ApiKeyEnvironmentVariable` 指定变量名，对应字段留空即可。

## 七、常见问题

**总结没有生成。** 在概览页查看"最近一次总结"的状态与失败原因；模型接口不可用时会自动重试并切换到备用模型。详细过程记录在日志目录中。

**推送未成功。** 检查飞书应用是否具备多维表格读写权限、是否对目标表格有编辑权限，以及列名是否与表格完全一致。设置页的"测试连接"与高级设置的"按列名自动匹配"可用于排查。

**识别不到文字。** 画面文字过少或过小时不会产生文字记录，这属于正常情况；可在抓取记录页确认识别结果。

**占用空间。** 截图按天数保留，记录与总结长期保留；两者均可在配置文件中调整。

**退出。** 关闭窗口只是收进托盘；请在托盘菜单或设置页中选择"退出 SnapLog"。

## 八、技术说明

- 界面：.NET 10 + Avalonia；托盘图标与截图接口使用 WinForms 组件。
- 识别：PaddleOCR（默认，离线运行）或 Windows 系统 OCR。
- 存储：SQLite 单文件数据库。
- 推送：飞书开放平台接口，使用应用身份（tenant_access_token）。
- 源码结构：`src/SnapLog` 按功能分目录——Capture（抓取）、Ocr（识别）、Core（流程与调度）、Summarization（总结）、Storage（存储）、Ui（界面）、Cli（命令行工具）。
