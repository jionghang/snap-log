# SnapLog 2.0

SnapLog 是一个 Windows 桌面工具。它在你切换窗口时记录屏幕活动、识别其中的文字，并在每天的设定时间把一整天的内容整理成一份工作小结，写入飞书多维表格。

程序常驻托盘，平时安静运行；只有在设定时间，才会把识别出的文字发送到你配置的模型接口。

---

## 一、适用场景

SnapLog 面向工作分散在多个窗口、多个系统之间的人。当天的内容事后再回顾，往往需要逐处翻找，也很难说清楚一天到底做了什么。SnapLog 在你正常工作的同时持续记录屏幕活动，并在每天结束时整理出一份按天归档的小结，自动汇集到飞书表格里，用于复盘、汇报或留档。

它强调的是平时不用管、到点自动有结果：记录内容始终保存在本机，发送的对象、时机与内容都由自己配置。如果你的需求是实时监控、跨设备同步或多人协作编辑，这个工具并不适合。

## 二、工作流程

程序平时只做一件事：当你切换到另一个窗口时，截一张图并识别出画面上的文字，存在本机。

每天在设定时间，程序按顺序执行三步：

1. **批量识别**：把前一天保存下来的截图统一识别成文字。
2. **生成总结**：把识别出的文字交给大模型，写成一份工作小结。
3. **推送飞书**：把小结写入飞书多维表格，一天占一行。

几条约定说明它的时间边界：总结的对象是已经结束的那一天，所以晚上加班的内容也会算进当天；如果设定时间电脑没有开机，程序会在下次启动后自动补执行；如果某一天生成失败或遗漏了，会在下一次执行时重做，不需要人工处理。

## 三、界面与配置

程序启动后驻留在托盘，首次运行会打开一个说明窗口，可从中进入设置。界面共有四个页面：概览、抓取记录、总结记录、设置。下面按页面说明各自的内容与配置方式。

### 概览

概览是程序的主页面，把四件事放在一个页面上。

- **记录状态**：页面顶部显示"正在记录"或"已暂停"，下方的按钮在两者之间切换。暂停期间不截图，也不会执行每日流程。
- **最近一次总结**：无需配置，自动显示最近一次的结果，包括覆盖的日期、用到的记录条数、所用模型、耗时，以及是否已推送到飞书。
- **每天自动执行**：一个开关加上一个时间。开启后，程序每天在设定时间依次执行识别、生成、推送三步。这是程序的核心开关，关闭后只做本地记录，不调用任何外部接口。
- **开机自动启动**：开启后，登录 Windows 时程序自动在后台启动并开始记录。

标题旁边的"?"按钮提供更进一步的说明。

### 抓取记录

这一页列出程序抓取到的屏幕记录，每行包括时间、进程、窗口标题、识别字数与状态。可以用关键词筛选，也可以用时间范围筛选，默认最多列出最近 300 条。

选择一行会打开记录详情窗口，里面能看到那一时刻的截图、识别出的完整文字，以及删除这条记录的入口。

### 总结记录

这一页列出生成过的每日总结，每行包括生成时间、总结日期、记录条数、飞书推送状态与生成结果。选择一行会打开总结正文窗口；正文可以选中复制，也可以打开程序保存下来的文本文件。

### 设置

设置页是接入配置，分三段。

**大模型配置**是生成总结用的模型接口。需要填的只有接口地址、模型名称与 API Key 三项，保存后可以点"测试连接"逐个验证。它支持配置多个模型：按顺序调用，前一个失败就自动换下一个，所以备用模型配好之后，主模型不可用时也能生成总结。只有处于启用状态的模型才会参与调用。

**飞书配置**是总结的推送目标。需要四个标识：飞书自建应用的 App ID 与 App Secret、多维表格链接中 /base/ 之后的部分，以及数据表 ID。App Secret 可以留空，改从环境变量读取。保存后，程序会把每天的总结写入对应的表格；同一天的总结只占一行，重复执行不会产生重复记录。

**其他**提供三个入口：高级设置、关于，以及退出 SnapLog。

### 高级设置

"高级设置"是设置页里的一个独立窗口，把更少用到的选项按用途分成四组：

- **记录范围**：勾选不参与记录的程序。清单取自历史记录里出现过的程序，不需要手打进程名。
- **总结偏好**：附加要求会原样追加到提示词末尾，用于补充自己的写作要求，例如"只写完成的事和结论"。
- **工作项目**：总结的主要工作主题按这里的项目分组；说明写得越具体，归类越准。
- **飞书字段映射**：左侧选总结里的字段，右侧填对应的飞书列名；也可以用"按列名自动匹配"读取表头后自动配对。

### 托盘

托盘图标提供完整的状态与操作：当前的记录状态、暂停或开始记录、打开 SnapLog、打开数据目录、退出 SnapLog。

注意：关闭主窗口只是收进托盘，程序仍在记录；要完全退出，请使用托盘菜单中的"退出 SnapLog"，或设置页中的同一入口。

## 四、安装与运行

直接使用：下载发布页的压缩包，解压到任意目录。这是自包含版本，不需要安装 .NET 运行时，双击 SnapLog.exe 即可运行。程序默认最小化到托盘。

从源码构建：需要 .NET 10 SDK。

```
build.cmd        构建（输出到 src\SnapLog\bin\Release\net10.0-windows10.0.19041.0\）
run.cmd          启动程序
publish.cmd      生成自包含发布版（输出到 publish\）
```

数据与日志都放在 `%LOCALAPPDATA%\SnapLog\`：数据库是 `activity.db`，截图在 `images\`（按日期分目录），生成的小结在 `summaries\`，日志在 `logs\`，配置文件是 `appsettings.json`。

## 五、隐私

截图与识别文字都保存在本机，不会主动上传到任何外部服务。只有在每天设定时间生成总结时，程序才会把识别出的文字发送到你配置的模型接口，默认只发送文字；是否附带截图，取决于大模型配置中的"发送内容"。推送到飞书的是总结正文及其元数据（日期、条数、所用模型等）。不希望被记录的程序，可以在"高级设置"的"记录范围"中排除。

## 六、配置文件参数

界面之外的参数集中在 `%LOCALAPPDATA%\SnapLog\appsettings.json`。程序在启动时读取这份文件，修改后需要重启才会生效；删除该文件则恢复全部默认值。

下面按用途分组列出可调整的参数。表中的"默认值"是程序没有配置时使用的值；任何一项都可以留空或删除，留空即使用默认值。

### 抓取

| 参数 | 默认值 | 含义 |
|---|---|---|
| `Triggers.CaptureCycleMinutes` | 10 | 同一窗口的抓取周期（分钟） |
| `Triggers.ForegroundSettleMilliseconds` | 5000 | 窗口切换后等待多久再截图（毫秒） |
| `Triggers.MinSecondsBetweenCaptures` | 20 | 两次抓取的最小间隔（秒） |
| `Triggers.ExcludedProcesses` | ["snaplog"] | 不记录的进程名 |
| `Triggers.ExcludedWindowTitles` | ["Program Manager"] | 不记录的窗口标题（精确匹配） |
| `Capture.MaxImageDimension` | 2560 | 截图最长边上限（像素） |
| `Capture.ImageRetentionDays` | 30 | 截图保留天数 |
| `Capture.ImageDirectory` | 空 | 截图存放目录；留空表示数据目录下的 images |

### 识别

| 参数 | 默认值 | 含义 |
|---|---|---|
| `Ocr.Engine` | PaddleOcr | 识别引擎：PaddleOcr（离线）或 WindowsMedia（系统内置） |
| `Ocr.Mode` | Realtime | 识别方式：Realtime（抓到即识别）或 ScheduledBatch（定时批量） |
| `Ocr.PaddleModel` | V6Tiny | PaddleOCR 模型档位 |
| `Ocr.PaddleThreads` | 4 | 识别线程数 |
| `Ocr.MinTextLength` | 4 | 少于该字数的记录标记为"无文字" |
| `Ocr.DropEmptyRecords` | true | 不保存未识别出文字的记录 |

### 存储与清理

| 参数 | 默认值 | 含义 |
|---|---|---|
| `Storage.DataDirectory` | 空 | 数据目录；留空表示 `%LOCALAPPDATA%\SnapLog` |
| `Storage.RecordRetentionDays` | 0 | 记录保留天数；0 表示不自动清理 |
| `Storage.DatabaseFileName` | activity.db | 数据库文件名 |

### 模型请求

| 参数 | 默认值 | 含义 |
|---|---|---|
| `Summarization.PayloadMode` | TextOnly | 发送内容：仅文字，或文字加截图 |
| `Summarization.MaxImages` | 6 | 附带截图时的最多张数 |
| `Summarization.MaxInputCharacters` | 24000 | 送入模型的记录正文上限（字符） |
| `Summarization.MaxRecords` | 200 | 送入模型的最大记录条数 |
| `Summarization.RetryCount` | 2 | 单模型重试次数（仅对可恢复错误） |
| `Summarization.RequestTimeoutSeconds` | 120 | 单次请求超时（秒） |
| `Summarization.SystemPromptOverride` | 空 | 完全替换系统提示词；留空使用内置提示词 |
| `Summarization.ExtraInstructions` | 空 | 追加到提示词末尾的写作要求（界面中可改） |

### 飞书推送

| 参数 | 默认值 | 含义 |
|---|---|---|
| `Feishu.PushLookbackDays` | 2 | 推送范围：只写最近 N 天生成且未写入的总结 |
| `Feishu.PushAfterSummary` | false | 生成总结后立即推送，不等定时推送时间 |
| `Feishu.MaxTextLength` | 2000 | 单条写入的正文上限（字符） |
| `Feishu.BatchSize` | 200 | 单批写入条数 |

### 日志与界面

| 参数 | 默认值 | 含义 |
|---|---|---|
| `Logging.Enabled` | true | 是否写日志文件 |
| `Logging.Level` | Info | 日志级别 |
| `Logging.RetentionDays` | 7 | 日志保留天数 |
| `Ui.StartMinimizedToTray` | true | 启动时只显示托盘图标 |
| `Ui.CloseToTrayInsteadOfExit` | true | 关闭窗口时收进托盘而不退出 |

密钥也可以放在环境变量中，避免写入配置文件：用 `AppSecretEnvironmentVariable` 与 `ApiKeyEnvironmentVariable` 指定变量名，并把对应的字段留空即可。

## 七、常见问题

**问：总结没有生成，是什么原因？**

在概览页的"最近一次总结"处查看状态与失败原因。模型接口不可用时会自动重试并切换到备用模型；具体过程记录在日志目录中，也可以在"关于"窗口里复制诊断信息。

**问：推送没有成功，怎么排查？**

依次检查三点：飞书应用是否具备多维表格的读写权限、应用是否对目标表格有编辑权限、列名是否与表格完全一致。设置页的"测试连接"与高级设置里的"按列名自动匹配"都可用于排查。

**问：为什么有些记录没有识别出文字？**

画面上的文字过少或过小时，不会产生文字记录，这属于正常情况。可以在抓取记录页查看该记录的识别结果与截图。

**问：它会占用多少磁盘空间？**

截图按天数保留（默认 30 天），记录与生成的小结默认长期保留。两者都可以在配置文件中调整。

**问：怎么完全退出？**

关闭主窗口只是收进托盘。要完全退出，请使用托盘菜单中的"退出 SnapLog"，或设置页中的同一入口。

## 八、技术说明

界面基于 .NET 10 与 Avalonia 构建，托盘图标与截图接口使用 WinForms 组件。文字识别使用 PaddleOCR（默认，离线运行），也可切换为 Windows 系统内置的 OCR。数据存储在 SQLite 单文件数据库中。推送走飞书开放平台接口，使用应用身份（tenant_access_token）完成认证。源码位于 `src/SnapLog`，按功能分目录，包括 Capture（抓取）、Ocr（识别）、Core（流程与调度）、Summarization（总结）、Storage（存储）、Ui（界面）、Cli（命令行工具）。
