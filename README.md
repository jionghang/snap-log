# SnapLog

一款运行在 Windows 上的屏幕活动记录工具。它在后台跟随前台窗口的变化截取画面，在本机把画面中的文字识别出来并存入数据库，需要时调用大语言模型生成工作总结，也可以把总结写入飞书多维表格归档。全部识别与存储都在本机完成，程序默认不联网。

## 应用场景

**工作复盘与工时统计**
一天结束时很难回忆起时间花在哪里。SnapLog 按窗口记录下当天打开过的应用、页面与其中的文字，生成按主题、按项目的总结，可以作为日报或周报的素材。

**事后查找信息**
记得在某篇文章或某个聊天窗口里看到过一段内容，但想不起出处。可以按时间范围、进程名或关键词在记录里检索，必要时直接打开抓取到的截图确认原文。

**汇报与归档**
需要定期向团队同步进展时，把每天的小结汇总成一份材料；也可以把小结写入飞书多维表格，与他人共享或接入仪表盘统计。

**个人时间审计**
查看哪些应用占用了最多时间、哪些切换属于分心。结合工作项目清单，可以看清时间在项目之间的分布。

## 主要功能

### 记录

- 跟随前台窗口切换触发抓取：窗口切换后等待设定时长，仍停留在同一窗口才截图，避免抓到尚未渲染完成的页面。
- 同一窗口在每个抓取周期内只记录一次，避免反复切换造成大量重复记录。
- 支持排除指定进程与窗口标题，密码管理器等敏感应用可以完全不被记录。
- 截取画面优先使用窗口自身的渲染内容，即使窗口被其他窗口遮挡也能得到正确画面。
- 支持按固定间隔定时抓取，与窗口切换触发可以同时启用。

### 文字识别

- 内置两种离线引擎：PaddleOCR（中文识别准确率更高，推荐）与 Windows 系统 OCR（占用最低）。
- 可选择实时识别，或每天定时批量识别：白天只截图，把耗用处理器的识别工作集中到空闲时段。
- 识别结果自动清理中文字符间的多余空格与界面噪声，便于阅读与检索。

### 检索与查看

- 记录查看器支持按时间范围、进程、状态、关键词筛选，分页浏览，查看每条记录的完整文字与对应截图。
- 支持批量删除记录，可选择同时删除对应的截图文件。
- 支持把当前筛选结果导出为 CSV。

### 工作总结

- 支持配置多个大语言模型，按顺序调用并在失败时自动重试与切换，提高生成成功率。
- 发送内容可选仅识别文字、文字与截图、仅截图三种模式；带截图时按时间间隔采样，控制调用成本。
- 支持维护工作项目清单，让总结按项目归类。
- 系统提示词可直接编辑，改动后立即生效，也可一键恢复默认模板。
- 总结历史完整保留，包括模型、尝试次数、耗时与失败原因。
- 定时生成按天补生成：尚未生成的天会补上；某天之后又有新记录时会重新生成并覆盖。

### 归档到飞书

- 可将总结写入飞书多维表格，一条总结对应一行。
- 字段映射可自行增删，目标表格中不存在的列留空即可跳过。
- 已写入的总结会打标记，重复执行不会产生重复行。
- 支持的触发方式：生成总结后自动写入、每天定时写入、手动写入。

### 运行方式

- 常驻系统托盘，托盘菜单提供开始与暂停记录、显示主窗口、退出三项操作。
- 支持开机自动启动，登录后最小化到托盘。
- 提供命令行模式，可执行抓取、生成总结、写入飞书、导出、清理等操作，便于接入计划任务。
- 内置界面自检与截图功能，便于排查界面问题。

## 安装与运行

**方式一：使用发布包（推荐）**

在仓库的 Releases 页面下载 `SnapLog-win-x64.zip`，解压到任意目录，双击 `SnapLog.exe` 即可运行。发布包是自包含版本，不需要预先安装 .NET 运行时。系统要求为 64 位 Windows 10 或更高版本。

**方式二：从源码构建**

需要 .NET 10 SDK。

```
dotnet build SnapLog.sln -c Release
dotnet publish src/SnapLog/SnapLog.csproj -c Release -r win-x64 --self-contained true -o release
```

仓库根目录提供了 `build.cmd`（构建）、`publish.cmd`（发布自包含版本）、`run.cmd`（启动）三个脚本，可直接使用。

## 首次使用建议

程序启动后常驻托盘，双击托盘图标打开主窗口，各配置集中在“抓取配置”“OCR 配置”“大模型配置”“推送配置”四页。

| 配置项 | 建议 |
| --- | --- |
| OCR 引擎 | 中文内容选择 PaddleOCR；机器内存紧张且对准确率要求不高时选择系统 OCR |
| 识别方式 | 日常使用选实时识别；希望降低白天资源占用时选每日定时批量识别 |
| 抓取周期 | 默认 10 分钟。周期越大记录越少，磁盘占用也越低 |
| 截图保留 | 默认 30 天。截图占用磁盘较多，建议按需设置上限 |
| 排除的进程名 | 建议加入密码管理器、银行客户端等不希望被记录的应用 |
| 大模型 | 填写接口地址、模型名称与密钥；密钥建议放在环境变量 `SNAPLOG_OPENAI_API_KEY` |
| 飞书 | 需要填写应用凭证、`app_token` 与 `table_id`，并完成权限配置，详见下节 |

## 数据与隐私

- 截图、识别文字、数据库与日志全部保存在本机，默认目录为 `%LOCALAPPDATA%\SnapLog`。
- 程序默认不联网。只有在主动执行“生成总结”或“写入飞书”，或者自行启用了相应的定时与自动写入功能时，相关内容才会发送至所配置的外部服务。
- 截图包含屏幕上的全部内容。首次使用前建议调整抓取周期与排除列表，并确认可以接受在本机留存这些画面。
- 调用大模型时会先在界面确认发送目标与内容范围；命令行方式提供 `--summarize --preview` 用于预览将要发送的内容，该预览不会发起任何网络请求。
- 密钥与令牌建议通过环境变量提供，不要写入配置文件或提交到仓库。

## 技术说明

- 使用 C# 与 .NET 10 开发，界面基于 Windows Forms，仅支持 64 位 Windows。
- 抓取采用前台窗口事件监听，空闲时不轮询，处理器占用接近零。截图按窗口自身渲染内容、设备上下文拷贝、屏幕拷贝三级策略依次尝试，可应对硬件加速窗口与遮挡场景。
- 文字识别全部离线运行：PaddleOCR 使用 PP-OCR 系列轻量模型，随程序发布；也可以使用系统内置 OCR 语言包。识别与缩放均在本地完成，不上传任何图像。
- 记录存放于 SQLite，启用 WAL 模式，支持按时间、进程、状态与关键词检索。
- 模型调用兼容 OpenAI 接口规范，可对接 OpenAI、DeepSeek、通义千问、Moonshot 等服务。
- 发布包体积较大（约 215 MB），主要来自 PaddleOCR 的原生推理库与模型文件；这也是它能够完全离线运行的原因。

## 已知限制

- 仅支持 64 位 Windows：PaddleOCR 的原生推理库只提供 win-x64 版本。
- PaddleOCR 比系统 OCR 慢。默认配置下识别一张全屏截图约需 4 至 6 秒，可用每日定时批量识别规避。
- PaddleOCR 免费社区版限制单次识别的文本块数量。内容密集的页面会自动拆块识别，耗时相应增加。
- 受保护内容无法抓取。数字版权保护画面与部分硬件加速窗口只能得到纯色画面，程序会记录说明。
- 已最小化的窗口无法抓取。
- 以管理员权限运行的窗口可能读不到进程名，标题与画面一般仍可获取。
- 系统内置 OCR 需要先安装中文语言包。
- 飞书多维表格写入需要同时具备接口权限与文档协作权限，缺失时飞书会返回对应的错误码，程序会给出中文提示。
